# Machine: Vaccine
Completion date: 09.16.2026

This machine had a simple start. I began by pinging the machine in terminal `ping <IP Address>` to ensure that I was properly connected to the network. The first step after this is to establish which ports are open. `nmap -sC -sV <IP Address>`, which showed me that ports for `HTPP`, `SSH`, and `FTP` were available.

Hack the box gave me a hint here in the phrasing of question 2, asking which username does not require a password for FTP. I began by trying Admin, Anonymous and Root. Anonymous allowed me access without a password, so I connected and looked through files available to me. The only available file was called backup.zip, I got a copy of the file, it was encrypted with a password.

First I tried some common passwords like `password, Password, Password123, etc` with no luck. So I used Zip2John to prepare the file password to be cracked. `zip2john backup.zip > hashes`. This put the hash for the password on backup.zip into a file called hashes, allowing it to be used with JohnTheRipper. `John ~/path/to/wordlist.txt hashes`. 

At this point I had problems with my driver, and I had to install tools like clinfo to find out which parts of OpenCL was missing. I had some parts of OpenCL that are required for Hashcat missing. After installing the proper driver, I was able to  re-run the haschat command. This then gave me the output `2cb42f8734ea607eefed3b70af13bbd3:qwerty789`, showing me the password being qwerty789.

Logging in showed a basic dashboard with filler information for cars. Searching for a car (I chose 'Vroom') shows that it uses a ?search command in order to search, which may be able to be exploited using sqlmap. I used cookie editor extension on my browser to copy the cookies for the login authentication, and submitted the command `sqlmap -u 'http://10.129.196.139/dashboard.php?search=vroom' --cookie="PHPSESSID=8q04n62vrd86lcvrs1q12i2cuq"` through sqlmap, which informed me that the search command may be vunlerable. I then could append that command with `--username` to find the username 'postgres'. I changed the username suffix with `--password`, choosing to do a dictionary attack with the default dictionary. SQLmap then returnede with user 'postgres' with password hash `md52d58e0637ec1e94cdfba3d1c26b67d01`, or clear-text password `P@s5w0rd!`. With this passwword I could now connect with ssh. once connected using ssh, I went to the home directory using `cd ~`, to find the text file `user.txt` which contained the first flag. `ec9b13ca4d6229cd5cc1e09980965bf7`

Next is to find the root flag. First I find the programs I can use as root using `sudo -l`. which informs me i can use vi (ViM), and also have root access to the file /etc/postgresql/11/main/pg_hba.conf. Given this inforatin I can use the ViM to get root access. `sudo vi /etc/postgresql/11/main/pg_hba.conf` gives me a text editor of the file etc/postgresql/11/main/pg_hba.conf. once this is established, I can set my terminal shell to root by using `:set shell=/bin/sh` followed by `:shell` which lead me back to the ssh menu on terminal as the root user. I confirmed this using `whoami`, which returned root. I went to the root folder `cd /root`, `ls`. This showed the file `root.txt`, which contained the final flag. A simple `cat root.txt` gave me the flag and I had completed the machine.
